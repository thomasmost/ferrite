# ferrite-sys — raw SDK bindings

Last verified: 2026-08-11

## Purpose
Raw FFI surface for the rePebble SDK, pinned to SDK 4.17 / Emery. Bindings are
**committed** so ordinary builds never need libclang.

## Contracts
- **Exposes**: everything in `bindings_emery` (glob re-exported), plus
  hand-written Rust ports of things bindgen cannot emit.
- **Guarantees**: struct layouts match what the firmware was built against —
  enforced by `const _` assertions, not by hope.
- **Expects**: consumers link against SDK 4.17 for Emery. The firmware call
  table is **index-based**, so a version mismatch corrupts silently instead of
  failing to link. Bindings and SDK version must move together.

## Boundary: never hand-edit bindings_emery.rs
It is `@generated by cargo xtask bindgen`. Hand edits are lost on the next
regeneration and, worse, would decouple the file from the headers it claims to
describe. Only two things belong in `lib.rs` alongside it:
1. Ports of function-like C macros (`GPoint`, `GRect`, `GColorFromRGB`, the
   named `GColor*` constants) — bindgen cannot generate these.
2. Compile-time layout assertions.

`PEBBLE_SDK_VERSION`, `PEBBLE_SDK_PLATFORM` and the `time_t` alias are
**emitted by the generator** into the generated file and reach users through
the glob. They are deliberately not restated in `lib.rs`: a stale hand-copied
version constant is worse than none.

## Bindgen flags that are load-bearing (see crates/xtask/src/gen_bindings.rs)
- `-fshort-enums` — the SDK is built by arm-none-eabi-gcc, which defaults to
  AAPCS short enums; clang does not. Without it, every struct with an
  enum-typed field has the wrong layout.
- `-D_TIME_H_` and `-Dtime_t=long` — **mirrored from the SDK's own compiler
  config**, not invented here. `pebble.h` includes `<time.h>` then defines its
  own `struct tm` and time prototypes; against newlib's header that is a hard
  redefinition error (real arm-none-eabi-gcc fails too). These defines are what
  make app C see Pebble's `struct tm` and a 32-bit `time_t`, so mirroring them
  is what makes our bindings match the real ABI. Because `time_t` is macro'd
  away before clang sees it, the generator emits the alias by hand.
- `Formatter::Rustfmt` (not Prettyplease) — otherwise the committed output is
  not in `cargo fmt` canonical form, `cargo fmt --all --check` fails on
  generated code, and `cargo fmt` rewrites a file that the next `bindgen`
  immediately rewrites back.
- `crates/xtask/stubs/` supplies empty `message_keys.auto.h` and
  `src/resource_ids.auto.h`; the real ones are generated per-project by the SDK
  build and do not exist at bindgen time.

## Invariants (the `const _` block, `cfg(target_arch = "arm")`)
Pins the ABI facts the safe wrappers rely on: 1-byte `GColor8`, packed `Tuple`
(7) and `AccelData` (15), short enums 1 byte except `AppMessageResult` (2,
because `APP_MSG_INTERNAL_ERROR = 1 << 15`), and `struct tm` at 48 bytes with
`tm_gmtoff` at 36 and `tm_zone` at 40. Offsets are asserted as well as size —
they catch field reordering or a padding change that preserves the total.
Ground truth was measured with real arm-none-eabi-gcc under the SDK's CFLAGS.

These only compile for the watch target, so a host-only `cargo test` does not
check them. If `bindgen` is ever run with wrong clang flags, the **target**
build is what breaks.

## Gotchas
- Generated code's lints are noise we cannot act on, hence
  `#[allow(nonstandard_style, unused, unnecessary_transmutes, clippy::all)]`.
  `unnecessary_transmutes` is a rustc lint, not clippy, so it needs naming
  separately — bindgen emits transmutes in packed-struct bitfield accessors.
- `cargo xtask bindgen` needs libclang (Apple Command Line Tools suffice) and
  the SDK at the default path or `PEBBLE_SDK_ROOT`.
